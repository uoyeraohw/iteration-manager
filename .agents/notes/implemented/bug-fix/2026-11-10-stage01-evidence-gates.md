# Agent Note: 第一批任务卡与完成门禁修复

Status: implemented

## Problem

任务卡范围表从第4节移到第5节，检查器未同步；严格分支参数未实际使用；缺少实证的DONE、Git命令失败均可能误放行。安装主版本不是Git仓库，不能以虚构提交作为恢复依据。

## Decision

只修改.codeg主版本，保留另外两个真实副本。先保存限定恢复快照；以稳定语义区域解析新卡、兼容旧卡；命令错误拒绝放行。完成门禁采用按类型JSON证据收据，绑定实现提交和冻结规格，并独立核对实际原始证据。工具只检查可机械验证的结构与版本关系；行为是否符合需求由独立审查者判断。

## Alternatives considered

- 继续按章节数字解析：改动最少，但再次插入章节就失效，故改为语义标记并保留旧格式适配。
- C后所有文件变化均推翻旧审查：规则简单，但后续无关任务会使整轮无法收敛，故核对任务自身范围并在分支层补足改动覆盖。
- 自动撤销白名单外文件：能快速恢复“绿色”，却无法证明改动归属，故只报告并保留他人工作。

## Testing

按解析、Git失败、范围、旧卡、分类型收据、规格/代码绑定、分支覆盖、模板同步与干净候选逐片取得有效断言RED和GREEN。命令、退出码与原始输出统一位于build/stage01-20261110/runs.jsonl及相邻日志。四种type在临时Git Worktree中运行真实严格CLI；夹具证据明确为synthetic，只验证门禁结构和版本关系。独立Antigravity验收结果及最终状态由docs/todos/01-stage01-gate-repair/README.md维护。

## Consequences

旧DONE可能第一次显露缺证据，严格门禁阻断其合流，不自动重写历史状态。有效审批绑定实现C及冻结规格，登记D和后续无关任务不推翻旧审查；范围内代码/测试/原始输出变化要求重审受影响内容。只读范围检查保留他人工作，但已有dirty归属仍需主管确认。新增收据和持久证据要求带来迁移成本；字段声明无法证明语义真实性与审查身份，仍由独立Reviewer核验原始材料。看板可信展示、助手自治及另外两副本同步仍在后续批次。
