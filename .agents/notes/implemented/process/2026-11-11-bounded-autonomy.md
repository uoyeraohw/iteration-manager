# Agent Note: 有界自治与统一助手协议

Status: implemented

## Problem

旧会诊模板要求清零轮次，没有累计预算、幂等事件或可靠恢复；三个助手与Skill内嵌Prompt可能互相覆盖。第一批证据门禁已经通过，不能通过旧卡豁免或自审降低门禁。

## Decision

任务卡持久化单一自治状态，保存事件ID、唯一写者与四类计数，原子替换并以临时排他锁串行写入。默认单轮5、累计10、会诊1、重规划2，可在启动前配置；恢复不清零，重规划只重置当前轮次。工具不充当调度器；代理状态查询、独立身份和授权仍由主控核实。三个权威助手Prompt引用同一协议，配置部署在阶段4。

unknown只表明当前查询方无可取记录，不证明执行者停止；原派发会话需补终态。桥接缺输入标NEEDS_INPUT与UNKNOWN，不虚构候选引用/证据。卡内事件为计数真源，fix_rounds仅兼容投影，策略冻结在启动时，不自动迁移或放大授权。

[单次检查点与命令入口](2026-11-11-checkpoint-resume.md)扩展时间中断后的显式续跑，保留本篇四预算与旧recover语义；成功事件派生独立上限3，真实预算熔断不解除。

运行时间另按全局绝对截止分配：主管继承剩余预算，叶子至少120秒工作窗口，硬截止前至少90秒只做收尾。run01将主管子树套入150秒后未产出RED，且外部BLOCKED未落卡；当前closeout动作要求真实会话终态、具体原因与项目内非空证据，从项目根原子登记FUSED/is_blocked并释放唯一写者，不改变四类计数，重复调用幂等。调度超时不冒称修复额度耗尽；原有额度耗尽原因不被覆盖。明确授权的父级先确认旧写者及子树终态，再release/claim/closeout做元数据恢复；未知命令状态留在阻断中，不启动业务重叠执行。

截止监控由scripts/deadline_watch.js在一次JavaScript工具执行内连续等待、读钟并取消；父级仍拥有派发/卡片/子树核对职责。派发前锁定deadline，不按实际启动时间后移承诺；默认提前10秒发出取消请求，分别记录请求和确认，并如实报告工具延迟。叶子命令前核对截止，同次调用保存输出与实际子命令退出码；补证取原持久工具结果，不将shell退出0当pytest通过。

## Alternatives considered

- 外部JSONL追加账本：便于审计，但和任务卡形成双写恢复问题；采用卡内事件记录，临时锁只串行写入，不另维护可变副本。
- 旧卡默认豁免：容易接管，但改变第一批UNKNOWN契约；接管先只读列差异，补验须授权，不伪造历史。
- 只生成Prompt也强制提交：保证运行基线，却越过用户只读意图；预览标注运行前门禁，只有实际执行才要求提交验证。
- 复用release收尾：保留旧接口且改动少，但它只释放writer，无法原子登记超时阻断；增加closeout，不重定义release。以fix登记超时会污染修复计数，未采用。会诊建议允许unknown时释放写者，违背既有终态核实契约，未采用。

- 仅将每次wait_ms缩短：改动最小，但等待返回后仍经过模型轮次，run02中02:47:33.541返回、02:47:49.654才发取消，跨过02:47:35承诺；改为单次工具内连续监控。只按实际创建时间后移截止可保足150秒，但会改写已承诺边界，未采用。

## Testing

build/stage02-20261111/runs.jsonl保存真实命令、时间、退出码及日志。有效断言RED覆盖旧入口重复计数、坏数据拒绝、envelope不读正文伪元数据、预算耗尽后的粘性阻塞及释放、旧卡报告、非法状态。新增API参数错误及fixture错误不算RED；跨进程、linked worktree和可配置预算为补充回归。

Antigravity压力01正确阻止清零和旧卡批准，但在缺输入的桥接Brief填了示例SHA，且把unknown解释为不活跃；据此补强协议。全新压力02实际返回UNKNOWN/BLOCKED、缺字段NEEDS_INPUT，原文保存在相邻evidence目录。独立验收状态以维护任务README为准，压力验证不充当终审。

本次closeout核心API取得真实断言失败RED，再取得GREEN；CLI未识别参数的初始失败不算行为RED。build/stage06-budget-closeout-20261111保留原始日志：自治回归17 passed，完整回归66 passed（133.18秒）。unknown/running、证据越界、外来owner、DONE与计数保留为补充回归；run02实际消费预算并执行closeout，但完整链未通过。原作者命令终态后从原生SQLite补证：pytest退出1、1 failed/29 passed，外层shell退出0；DONE断言失败，FUSED断言尚未执行。补证不追认旧交付为PASS。截止守卫6项受控时钟回归、助手来源合计8项通过；完整回归72 passed（132.85秒），真实时钟工具执行器本地回调探针预留200ms取消余量，实际在1200ms截止前193ms发起并确认取消（不是Codeg代理链）；真实多代理消费和独立验收受Antigravity额度限制，状态见docs/todos。

## Consequences

旧调用没有显式事件ID，按实现引用和错误摘要去重；新调用必须提供稳定ID。卡片手工篡改不能靠脚本证明身份，需要独立审查原始证据。临时锁崩溃遗留时不自动移除，须先核对无活动写者。预算策略变更需要明确迁移，不提供暗中清零。新增协议增加落盘字段，但移除了重复调度说明。

既有[第一批证据门禁决定](../../implemented/bug-fix/2026-11-10-stage01-evidence-gates.md)部分重叠，保留其C/D和旧卡UNKNOWN契约，不归档不重写。看板、部署与真实新会话消费仍由第三批负责。

[分层验证与可交付检查点](2026-11-12-bounded-validation-workflow.md)补充主控的就绪检查与无进展重派限制，保留本篇事件、预算、截止与终态合同；第一批交付时仅由主控执行规则，未增加脚本动作；后续显式脚本入口见[就绪检查与无进展门禁](2026-11-12-execution-readiness-guard.md)。
