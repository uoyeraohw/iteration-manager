# Agent Note: 分层验证与可交付检查点

Status: implemented

## Problem

AIMovie会话1450暴露了无效UI证据返工、超时后重新读取以及业务收口混入工具兼容迁移。原模板在GREEN阶段要求项目全量回归，UI模板又固定语言、工具与桌面/移动视口；这些默认项会放大交接成本。现有记录不能拆出测试编写与代码编写各自耗时，不能将整个会话时长称为TDD耗时。

本次用户只授权第一批规则与模板优化，保留真实验证与独立审查；脚本、AIMovie任务迁移和第二批实施均不在本次范围。

## Decision

共同协议集中定义只读就绪检查、角色合并、可交付检查点、无进展重派限制、分层验证与证据复用。模板只填本次执行所需输入和产物，不再在每次GREEN默认安排全套回归。

- 普通任务主控可兼任主管，同一实现者承担核心RED/GREEN及返修；指定执行者与角色分离要求优先，独立Reviewer仍须非参与者。
- 正常阶段交付后核实会话/命令终态并release；真正时间中断仍closeout/FUSED。连续两次没有可用新增证据时，必须先改变输入、切片或能力条件，不原样重派，也不新增或清零预算。
- 开发内环运行针对性测试，任务交付保留type必需checks与受影响回归，迭代收口保留集成路径、全量回归与独立总审。旧任务明确规定的全量检查不自动缩减；影响不明扩大验证。指定独立复验仍实际运行。
- UI先从真实入口完成一条代表路径，再扩展约定矩阵。诊断用DOM/store/内部API不充当真实交互；媒体状态用原生事件与状态证明。技术栈、样式机制与视口沿用项目约定。
- 新迭代执行约定放在README冻结目标区域，固定真实工具入口和版本。插件升级、收据迁移与业务交付分别授权；iteration-delivery.json仍精确两键。
- Git与FS审查后变更规则分别表达。FS完整正文先定稿再冻结，不预写尚未发生的APPROVED；审查结果写在收据及允许的元数据中。既有冻结绑定及checks没有放宽。
- 新候选可沿用经核实未受影响的旧测试输出，但保留其原执行归属；受影响检查重跑，原收据失效后须新独审与绑定收据。输出复用不等于批准复用。

第一批交付时就绪检查与无进展限制由主控按规则执行，未提供新CLI、事件字段或自动拦截能力；后续已授权的[第二批脚本](2026-11-12-execution-readiness-guard.md)提供显式新入口，不追溯迁移旧调用。FS检查点续跑仍未实现，不能套用Git grant。第一批不修改scripts或tests，不部署助手配置/独立安装副本，不提交Git，不迁移旧卡。

## Alternatives considered

- 提高超时与修复预算：能减少中断，但不能解决相同输入重读和无效证据；保留原预算，先要求可继承产物与改变重试条件。
- 移除真实UI或独立审查：收口更快，但AIMovie的结果归属、关闭后媒体未暂停等真实缺陷会失去检出路径；保留门禁，减少无依据的重复执行。
- 一次实现自动preflight、事件统计与FS恢复：可把规则落为硬门禁，但超出本次第一批授权；本批明确人工执行边界，后续须用户确认。

## Testing

修改前的实际代理基线场景确认：4分钟窗口无法满足原模板8分钟全量回归；两次超时后缺少明确无进展拦截；UI桌面任务与模板桌面/移动要求冲突。真实AIMovie历史失败作为问题依据，本次场景不冒充业务复验。

针对性验证、场景消费和非参与者独审记录在 `build/batch1-rules-20261112/`。来源/任务模板测试最终4项通过（0.42秒），现有解析器及FS转换/冻结投影探针通过，笔记tree/format及归档检查通过。新上下文的A/A2/B/C/D/E场景分别覆盖短窗口、新旧全量要求、无进展重派、真实UI、FS冻结/恢复和审查独立性；均给出有边界的执行决定，不等同真实业务验收。

首轮独审提出FS模板转换不够具体、envelope不含FS候选ID、跨候选复用歧义。本次增加逐项转换步骤、要求另读卡片/收据核对candidate_id，并明确沿用输出与新批准的区别；聚焦复核记录另见证据目录。场景中对普通桌面像素缺省产生不必要NEEDS_INPUT，模板补为采用项目既有/实际视口并记录，不增加确认门禁。未运行AIMovie测试、未测脚本新能力，不能据本批宣称实际节省了某个比例的耗时。

第二位非参与者聚焦复核确认三项均有对应修正，另指出candidate_id与文件路径并列的措辞歧义。主代理将ID及三类路径拆为独立槽位并定点核对，不重开无关全量验证；最终交付判断由主代理作出，不将Reviewer的NEEDS_FIX信号改记为APPROVED。

## Consequences

减少机械层级和默认重复全套验证，同时保留真实行为、失败路径、独立身份与冻结绑定。代价是主控仍须准确选择受影响范围并检查重试是否新增证据；当前脚本不会自动执行这些新调度规则。实际耗时收益需未来获准的真实迭代观察，本批不据模拟场景估算。
