# Agent Note: Codeg技能主版本的Git基线与独立副本同步

Status: implemented

## Problem

三个技能安装目录原本均非Git仓库，无法执行用户要求的主分支交付。用户明确授权在Codeg目录初始化Git，并用其覆盖更新Codex、Gemini副本；需要让后续版本有可追踪基线，同时保留原始验收和恢复材料。

## Decision

`.codeg/skills/iteration-manager` 是唯一Git源码仓库，默认分支为 `main`。首次提交记录当前真实源码、模板、测试、决定与维护任务；不迁造过去的提交或合并历史。仓库本地关闭自动换行转换，保留已批准文件的原始字节，不修改全局Git配置。

两个技能库继续是独立安装目录，不复制 `.git`，也不改成链接。同步范围沿用[助手部署与副本交付决定](2026-11-11-assistant-deployment.md)：SKILL、scripts、references、templates、tests及决定记录；不复制维护任务、build、运行证据、缓存和历史备份。覆盖前逐文件备份，遇到新增、并发修改或不明活动文件时停止处理，不删除目标独有历史材料。

本决定与上述部署笔记部分重叠，保留其配置部署和新会话消费契约，不改写旧笔记或冻结快照。其它历史门禁、预算、收据与AIMovie业务工作区不受本次Git初始化影响。

## Alternatives considered

- 保持非Git并继续快照交付：可完整沿用既有证据，但没有可供以后迭代使用的主分支，用户已明确选择初始化Git。
- 把整个主版本目录连同 `.git`、build和缓存复制到两个技能库：目录表面完全相同，但会复制验证沙箱、恢复材料和仓库内部状态；沿用限定交付清单，避免把安装副本变成源码仓库。

## Testing

Git分支、暂存清单及初始提交实际检查；新增笔记运行tree/format校验。同步逐文件直接比对，验证两个实际安装入口；原57份R7活动文件与批准冻结候选保持相等。实际命令、退出码、备份与恢复清单位于 `build/git-init-sync-20261112-120855/`，最终状态见维护任务09。

## Consequences

后续可在真实源码仓库使用分支和提交，两个技能库只消费受控交付。Git历史从本次初始化开始；更早的证据继续保留在本机build目录，未纳入Git，不能仅靠克隆恢复这些历史材料。主版本维护文档和Git元数据不会出现在安装副本中，同步需要继续遵守明确清单。
