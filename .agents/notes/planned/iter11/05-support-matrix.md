# 任务05：证据边界与支持矩阵

## Context
历史发布、当前平台快照、宿主执行与安装消费有不同候选和证据，混为单一“支持”会误导消费者。既有[文件系统决定](../../implemented/architecture/2026-11-12-filesystem-delivery.md)与[完整正文绑定修正](../../implemented/bug-fix/2026-11-12-filesystem-r7-acceptance-repair.md)保留本地绑定边界；检查点合同明确FS grant不支持。

## Decision
按能力、平台、宿主、状态、时间、候选、原件和限制逐行表达观察；来源支持、实测、独审、安装和消费分别描述。release_status只新增矩阵路由，不重写历史。未知项列责任人及客观补证条件；不以新矩阵建立第二状态账。

## Alternatives and consequences
直接把历史发布标为当前支持会隐藏时间和环境差异；仅列源码能力无法回答实际宿主情况，均不采用。历史证据不属于既有安装白名单，维护仓库链接可解析但安装副本不保证完整，离线证据包须另获授权。结构检查只验证格式和路径，独立审查与新会话解释仍需实际进行。
