# 安装来源清单的绑定与能力边界

Status: planned

交付白名单采用已有发布范围。生成时以实际完整 Git commit 的 tree 和 blob 为来源，比较源目录白名单完整集合及字节；拒绝额外、缺失和符号链接项，避免把提交标签当成内容证明。忽略文件也视为额外交付文件，可能要求调用者先在隔离干净源码树生成清单；不替用户清理。

独立副本不包含 Git，无法仅凭摘要证明清单真实性或提交确实存在。检查要求可信清单并核对集合及字节，报告清楚标明信任边界；签名、联网来源证明及部署不在本卡。目录假定没有并发替换，若未来需要敌对并发防护，应另设计目录句柄相对访问。

能力观察白名单文件、Linux pidfd API 与 proc 访问前提；不执行查询、runner 或 OS 原语。后端或可观察的前提缺失为 UNAVAILABLE，存在也仅 UNKNOWN，完整链不宣布 READY；这是轻量只读与实际执行证明之间的取舍。Linux 与 Windows 均有源码后端，但 Windows 当前执行证据缺失。详见 `references/installation_verification.md`。
