# 新重构任务的量测证据

此规则用于未来新规划的 Refactor-Benchmark 卡；已冻结卡及其明确要求继续适用。沿用 schema 1、四个 type 和五项检查：baseline、regression、compatibility、benchmark_before、benchmark_after。baseline 是行为测试基线，regression 覆盖受影响行为，compatibility 是公共接口兼容观察，前后量测是成功命令及其原始输出；独立审查和收据绑定仍按任务卡契约执行。生成和结构预检不判断指标是否符合目标，也不构成执行或批准。

## 按目标选择可比实测

- **行为保持、结构目标**：先声明外部行为与兼容范围、结构目标、可重复客观指标、计数规则、测量命令、候选、环境及范围；例如指定模块之间的依赖边数或指定目录的重复入口数。before/after 分别实际运行同一定义和范围，记录条件、原始数值、单位、变化和目标判断。无性能目标时不强制延迟或吞吐改善；结构数量不是性能证据。
- **性能目标**：明确性能指标（如延迟、吞吐或资源占用）、目标及单位，在可比环境、数据规模、工作负载、命令和计量方法下取得真实 before/after 数值和原始输出，记录候选、条件、变化及是否达到目标。结构指标可辅助解释，不能代替性能实测。合成工作负载只支持其明确范围内的结论，不是生产负载或实际业务通过证据。
- 两类目标同时存在时分别满足两类证据。无法取得指标或无法比较时保持 UNKNOWN/BLOCKED，不以结构计数、空值、估算或生成卡代替实测。约定的重复次数、平台迁移、既定任务更严格要求均不因本规则降低；例如迭代 11 的 07 仍按授权 Linux 迁移保留相同方法的各三次 before/after 耗时与依赖数量，不声称提速。

规划时将上述条件写入现有 objective、acceptance 和五个 verification 文本，不新增必填元数据或 type。评审者应核对实际命令、原始条件和结果、兼容性、受影响回归及独立性；文本非空只证明形状。
