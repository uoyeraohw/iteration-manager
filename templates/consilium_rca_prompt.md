# 会诊：根因与可执行路线

遵守 [共同执行协议](../references/agent_protocol.md)。达到单轮修复上限后停止修复；先登记会诊事件并确认预算，再按用户路由委派。默认单轮5/累计10/会诊1/重规划2，实际读取任务卡配置与持久事件。

## 输入

- 任务卡：`{task_file_path}`
- 迭代：`{iteration_name}`
- 实现引用：`{base_sha}..{head_sha}`
- 授权范围：{files_changed_list}
- 原始失败与已尝试假设：{error_stack_summary}
- 补读卡内预算、接口、ledger及证据；缺证据列出UNKNOWN，不推断通过。

## 返回

1. 根因假设及直接证据，区分实现、测试、依赖与设计问题。
2. 既有假设为何失效、是否引入回归。
3. 推荐路线及真实备选：具体改动、授权边界、验证、成本与恢复条件。
4. 影响哪些冻结契约和后继任务，何处需要权限持有人决策。

主控先核对正确性、契约、范围与授权，再在iter:ledger第7.3节登记Ruling，不自动采纳方案A。若需要重规划，使用 `--autonomy replan`登记稳定事件ID、理由及会诊/授权证据；仅重置当前轮次，累计不清零。达累计或其它上限保持FUSED/BLOCKED并交付恢复条件，不能手工清零后继续。会诊参与者不是本任务独立Reviewer，会诊结论不产生APPROVED。
